A Git conflict (merge conflict) happens when Git cannot automatically decide which change to keep because two people modified the same piece of code differently.

Example

Suppose the original file contains:

C#
string name = "Customer";

Show more lines
Developer A changes it to:
C#
string name = "Account";

Show more lines
Developer B changes it to:
C#
string name = "Contact";

Show more lines

When Developer A merges first, main becomes:

C#
string name = "Account";

`

Show more lines

Now Developer B tries to merge. Git sees:

Main branch says: "Account"
Developer B's branch says: "Contact"

Git doesn't know which one is correct, so it creates a conflict.

How a Conflict Looks

Git marks the conflicting section like this:

C#
<<<<<<< HEAD

string name = "Account";

=======

string name = "Contact";

>>>>>>> feature-branch

Show more lines

Meaning:

<<<<<<< HEAD = current branch (main)
======= = separator
>>>>>>> feature-branch = incoming changes
Resolving the Conflict

A developer manually decides what should remain.

Keep Account:

C#
string name = "Account";

Show more lines

Keep Contact:

C#
string name = "Contact";

Show more lines

Or combine both:

C#
string displayName = "Account Contact";

Show more lines

Then commit the resolution:

Shell
git add .

git commit -m "Resolved merge conflict"

Show more lines
Real D365 CRM Example

Imagine two developers are editing the same JavaScript file:

Developer A

JavaScript
formContext.getAttribute("name").setRequiredLevel("required");

Show more lines

Developer B

JavaScript
formContext.getAttribute("name").setRequiredLevel("none");

Show more lines

When merging, Git can't determine whether the field should be required or not.

A conflict occurs and the team must decide the correct business requirement.

When Conflicts Usually Occur
Two developers modify the same file and same lines.
One developer deletes a file while another edits it.
A branch is old and hasn't been synced with main for a long time.
How to Reduce Conflicts

✅ Pull latest changes regularly

Shell
git pull origin main

Show more lines

✅ Create small feature branches

✅ Merge frequently

✅ Communicate with team members when working on the same files

✅ Review incoming changes using Fetch before merging

Simple Analogy

Imagine two people editing the same sentence in a Word document:

Original:

"Customer Name"

Person A changes it to:

"Account Name"

Person B changes it to:

"Contact Name"

When combining the documents, someone must decide which text is correct. That's exactly what a Git conflict is
