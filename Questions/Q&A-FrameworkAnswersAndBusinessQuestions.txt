Example - 
In D365, when multiple security roles are assigned to a user, the system follows a cummulative privilege model. This means privileges from all roles are combined, and the highest level of access is applied for each privilege.
For example, if one role gives User-level read access and another gives Business Unit-level access, the user will get Business Unit-level access.
There is no deny concept in D365 security; access is always additive and evaluated based on the most permissive level.

One challenging situation I encountered was in a Dynamics 365 Field Service implementation where activating a Preventive Maintenance Agreement automatically generated Work Orders for all customer assets covered under that agreement. Some customers had hundreds of assets, so a single agreement activation could result in the creation of several hundred Work Orders along with related records such as service tasks and resource requirements. Initially, this process was implemented through a synchronous Post-Operation plugin. The plugin retrieved data multiple times, fetched unnecessary attributes, executed Dataverse queries inside loops, and created records individually. As the volume of assets increased, users started experiencing slow response times during agreement activation because the plugin was making a large number of Dataverse calls and spending significant time communicating with the database. To address this, I first analyzed the plugin execution flow to identify performance bottlenecks. I optimized the data retrieval by replacing multiple retrieve operations with a single RetrieveMultiple query and limited the data being fetched by retrieving only the required columns instead of using ColumnSet(true). I also eliminated redundant queries and reused reference data wherever possible. For record creation, I implemented batch processing using ExecuteMultiple to reduce the number of Dataverse round trips. Additionally, I recommended moving the heavy processing to an asynchronous approach so that users would not have to wait for hundreds of records to be created as part of the same transaction. As a result, the agreement activation process became significantly faster, the number of Dataverse calls was reduced considerably, system scalability improved, and the overall user experience was much better. The key takeaway from this challenge was understanding how to balance business requirements with platform limitations by optimizing queries, reducing service calls, and choosing the right processing model for large-volume operations.

Q.Can you share an experience where post-deployment support was crucial?
Yes, post-deployment support was crucial in one of my Dynamics 365 Field Service projects where I implemented technician scheduling automation.

After the solution went live, users reported that the scheduling process was taking longer than expected during peak operational hours. The scheduling logic needed to evaluate multiple factors such as existing bookings, technician availability, working calendars, and other constraints before assigning a resource.

During the support phase, I analyzed the implementation and identified that the custom logic was querying multiple entities separately to gather the required information. While the functionality was working correctly, the approach resulted in additional database calls and increased response times as the volume of bookings grew.

To address this, I redesigned the solution to leverage Dynamics 365's native Web API capabilities and optimized the data retrieval strategy instead of querying each component individually. I also refactored the code structure to reduce redundant operations, improve maintainability, and enhance overall performance.

As a result:

Reduced the number of database calls significantly.
Improved scheduling response times and user experience.
Enhanced scalability as the number of technicians and bookings increased.
Reduced manual effort for dispatchers who previously had to verify technician availability and calendars manually.
Increased stakeholder confidence in the solution after go-live.

Key takeaway: This experience taught me that post-deployment support is critical because real-world usage patterns often reveal performance bottlenecks that may not be evident in UAT or lower environments. Proactive monitoring, performance optimization, and user feedback were essential to ensuring the long-term success of the solution.
